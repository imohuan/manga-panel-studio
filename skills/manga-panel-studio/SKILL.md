# 漫画画布 OCR 校对与配音脚本

## 开工第一件事（必须，不许跳过）

在敲任何命令之前，先跑这一条，把它的输出原样转述给用户：

    python canvas_cli.py plan <会话>

它会打印会话名、页数、数据目录、实时地址、步骤和节奏。开会话之前
（还没 init）就先按下面四样口头说清楚：

    - 会话名 + 一共多少页 + 数据在哪个目录
    - 打算怎么做：OCR 排队 → next 逐页取 → 校验修框 → 写 md → 写 audio_scripts
    - 实时地址：http://127.0.0.1:7788/?s=<会话>   ← 用户随时能自己看进度
    - 大概要多久（比如 43 页，每页 20-40 秒）

**地址一定要给**，别等做完才说。用户看不见你的终端，只能靠这个页面知道你在干什么。

说完这段再开跑。`ocr` 一秒内就会返回，它不会卡住，所以没有什么「等我先跑完再汇报」的理由。

## 这个技能做什么

把会话目录（默认 ~/.manga-panel-studio/sessions/<会话>/）里的漫画图片，经过「整页 OCR → 逐页检查图校对 →
修框 → AI 理解写 md → 配音脚本 → 声纹与对话音频」变成可配音的分镜数据。

## 零、前置条件与应用启动（先读这一段）

### 本技能建立在 npm 包 manga-panel-studio 之上

技能装好后，**先确认应用本体已安装**。画布服务（7788）由 npm 包提供，
没有它整套流程都跑不起来：

    npm list -g manga-panel-studio   # 有输出 = 已安装

没装就先装（一条命令，零依赖秒装完）：

    npm install -g manga-panel-studio

装好后用包自带的命令启动/检查服务：

    manga-panel-studio          # 启动画布服务（前台运行）
    manga-panel-studio ocr      # 启动 Python OCR 服务（5009，后台）
    manga-panel-studio start-all  # 两个都起（OCR 后台 + 画布前台）
    manga-panel-studio check    # 查 7788 / 5009 两个服务的状态

判断方法：`manga-panel-studio check` 通了就直接用。

`manga-panel-studio ocr` 会自己判断情况并说清楚：

- 5009 已健康 → 直接复用，不重复启动；
- 端口被别的进程占着 → 打印 netstat / taskkill 的具体命令；
- Python 路径不存在 → 让你去设置页填 manga-image-translator 目录；
- 启动后崩溃 → 直接打印日志最后 12 行（真实报错，不是「请稍后重试」）；
- 正常 → 等到 health 就绪才返回 OK。

### 第一步：看一眼配置有没有填

配置存在 ~/.manga-panel-studio/settings.json（npm 安装时自动从模板创建；
路径可用 STUDIO_SETTINGS_FILE 覆盖）。开始干活前先跑：

    $env:PYTHONIOENCODING='utf-8'
    python canvas_cli.py doctor

它**只读文件**，不启动、不重启任何服务，所以很快，可以每次都用。

- 打印「配置已存在」→ 直接往下做，别再多跑探活。
- 打印「配置还没填：……」→ 这些项缺了。这时确保画布服务在跑
  （没跑就 `manga-panel-studio` 启动，已在跑就直接用，别重启），
  然后用浏览器打开 **http://127.0.0.1:7788/settings.html**，
  doctor 也会自己打开。告诉用户缺哪几项、设置页已打开，等用户填完再继续。
  不要猜 key，也不要往 settings.json 里写假值。
  如果页面没自己弹出来，就用 browser-control 技能新建标签页打开这个地址
  （它走用户的 Chrome）；打开后用 `tab.markDeliverable()` 留住，方便用户填写。

要检查的配置一共五项：OpenAI 的 Base URL、API Key、模型；豆包 API Key；
OCR 服务地址。

退出码：0 = 配置都在；2 = 有缺项（已打开设置页）。

识别服务 5009 只在要跑 OCR 时才需要，那时候没起就 `manga-panel-studio ocr` 拉起
（Python 解释器自动从 ~/.manga-panel-studio/settings.json 的 translator.projectRoot
推导；没填这个目录就先让用户在设置页里填 manga-image-translator 的位置，没装 MT
就先让用户装）。

刚启动要 20-40 秒加载模型。想看两个服务通不通，用 `python canvas_cli.py check`。

### 完整流程

    1. ocr        生成第一个 json（框 + 文字）
    2. AI 校验     找出漏框、噪声框、读错的字
    3. 修框        scrub / view 给的命令 / fix
    4. AI 读图写 md                ← 默认终点
    5. AI 依 md 写 audio_scripts    ← 默认终点
    6. vp         生成声纹          ← 需明确要求
    7. dlg        用声纹生成对话音频 ← 需明确要求

**默认只做到第 5 步就结束。**
第 6、7 步要花钱，且不是每次都要，**只有用户明确说「生成声纹」「生成音频」
或「跑完整流程到最后」时才做**。没被要求就跑 vp / dlg = 越权消耗额度。

### 流水线作业（重要：不要等整本 OCR 跑完）

开场那段计划在文档最前面已经写过（会话/页数/流程/实时地址），照着说一遍就开跑。

整本 40+ 页的 OCR 要好几分钟。**不要阻塞等待全部完成**——ocr 只负责排队，
哪一页识别好了就立刻拿它往下做（校验 → 修框 → 写 md），一页一页往前推。

标准循环：

    1. ocr <会话>            # 只排队，立刻返回
    2. next <会话>           # 取最早一页「已识别但还没写 md」的页号
       → 打印 00001 就拿它做第 3-5 步；退出码 1 = 暂时没有可做的页，
         等 20-30 秒再来一次（这期间不要空转，可以给用户报进度）
    3. scrub <会话> 00001    # 清噪框
    4. view <会话> 00001     # AI 校验；FAIL 就按它给的命令修，再复验一次
    5. 读原图 + show，写 00001.md 和 00001_audio_scripts.json
    6. 回第 2 步取下一页，直到 next 说没有可处理的页、队列也清空

**流水线动作会自动进历史**：`ocr` 排队和 `next` 取页都会写一条记录，
用户在画布右侧「历史」面板能看到 `OCR 排队 N 页` 和 `流水线取页 -> 00001`，
展开还有页号标签。所以汇报进度时可以直接说「历史面板里能看到我跑到哪一页」。
这两条记录由 CLI 自动写，**不要**手工调用 `/pipeline` 接口。

三条硬规则：

- **ocr 没有任何等待参数**（`--wait` 已删除），它永远立刻返回。
  也禁止自己写轮询脚本等整批完成：48 页项目实测死等十几分钟、零产出，
  必须用 `next` 一页页往前推。
- **一开始就把实时地址给用户**：`http://127.0.0.1:7788/?s=<会话>`。
  用户自己就能看框、看 OCR 进度、看历史。每做完几页再报一次「已完成 N/总页数」。
  不要等全部做完才提这个链接。
- 收尾自检（check-characters / check-audio）等所有页都做完再跑。

### 节奏

- 每页最多 **1 次 view 校验 + 1 次复验**；三页并行约 15 秒。
- **FAIL 的闭环**：view 报 FAIL 后，按它给的 [CMD: ...] 逐条执行修框，
  然后对该页复验一次；复验 PASS 才算这页完成，复验仍 FAIL 且剩余问题
  属于「水印/页码/签名等确认非正文」的，可以不再修，但必须在最终回复里
  说明剩余项和跳过理由。**不允许 FAIL 未处理就直接写 md**。
- 全程不逐框放大、不手工截图对比、不核对错别字（除非意思读反）。
- 用 CLI 一条命令完成一件事，不要多条命令拼同一个动作。
- 收尾自检：框校验超过 2 分钟，就是走弯路了。

出现下面任意一条，立即停下，回到「scrub 一次 + view 一次」的流程：

    - 建 _check 目录、下载 p3_full.jpg / p3_n0.jpg / p3_n1.jpg… 十几个局部图
    - 写 md 时为了「确认说话人」再去下载局部放大图（v4 的翻车点）
    - 为同一个框反复调 rect 坐标，一次只挪十几像素
    - 删框后继续用旧编号删，删错行再来回补
    - 逐条核对 OCR 错别字（「财围」「夏然而止」这类）
    - 已经 PASS 过的页又重跑一次 view

## 二、铁律

- **开始任何操作前先跑 `python canvas_cli.py doctor`**（见「零、第一步：看一眼配置有没有填」）。
  它只读 settings.json：齐全就直接开工；缺项才启动画布服务并打开 /settings.html。
  配置没填完时等用户在设置页填好，不要猜 key。
  画布服务如果本来就在跑，绝不要为了「让它生效」重启它。
- **写入只能走 CLI（canvas_cli.py），禁止直接改 sessions 下的 json**。
  CLI 走画布 HTTP 接口写入，才留历史、SSE 广播、前端实时刷新。
  `ocr` 与 `next` 会自动写 `pipeline-ocr` / `pipeline-next` 历史记录；
  用户可在历史面板看到流水线进度。要新增其它可视化记录，
  参考 <仓库>/docs/pipeline-history.md。
- **看图只能用 /render 检查图接口，禁止自己写 Pillow 脚本裁图。**
- **框的校验一律用 canvas_cli.py view，不要自己下载渲染图看**。
  view 已经把「拉整页预览图 + 读框数据 + 判断漏框/噪声框/空框」打包成一次调用，
  并直接给出可执行的修复命令。自己下载图片再看，等于把同一件事重复三遍：
  慢、且容易越看越细。整页一次看完就够，不要逐框放大。
  （view 超时/报错时原样重试一次；仍然失败才考虑手工看图，并在报告里说明。）
- **框只有新增（add）和删除（rm），没有编辑**。改文字 = rm 旧框 + add 新框。
- **md 与对话文本默认中文**。OCR 结果是英文/日文时，md 里翻译成中文保存；
  json 里 region.text 保持原样；除非用户明确指定目标语言。
- **错别字分级处理**：单个错别字（形近字误识，读者能看懂原意的）一律不管，
  跳过不改；只修「意思完全错误」或「文字逻辑错误」的框——词不存在、
  主谓宾断裂、语义反转这类。判断标准：读者读到这里会不会误解剧情。
  这样能把修字命令量从几十条压到几条。
- **OCR 结果只是草稿**。画布整页 OCR 只跑一遍检测，必然有噪声框和漏框；
  每页必须过一遍 view 校验后才算完成，但只过一遍。
- **框只要罩住文字就行，不要追求精确贴合**。padding 大小无所谓。
  边界轻微偏移但文字完整覆盖 = 通过。整页视角下看着正常就不要再放大。
- **禁止逐框放大核对**。v2/v3 实测：每页逐框放大要 30-60 次取图，
  占掉整个任务一半以上时间，而检出的问题用 view 一次就能全部列出来。
  只有 view 明确报了某个坐标的漏框、且整页图上确实看不清时，才允许对该点放大一次。
- **写 md 只看一次整页原图，再结合一次 show**。原图定「画了什么、谁在说」，show 的文字定「说了什么」。
  **不许下载、裁剪、放大任何局部**，v4 实测连下 12 张局部图，把 3 分钟拖成 10 分钟。
- **发现新角色必须立刻写入 characters.json**。只要对话或画面里出现
  一个之前没见过的角色（含未知角色），马上把 外貌描写 + 声线特征 写进
  会话级 characters.json，不允许留空。角色档案字段：
  name / appearance / voiceprint_desc / voiceprint_audio / api_ref_audio / final_ref_audio。

## 三、CLI（canvas_cli.py）

    位置：<仓库>/skills/manga-panel-studio/scripts/canvas_cli.py
Windows 控制台先执行 $env:PYTHONIOENCODING='utf-8'。

    python canvas_cli.py check                          # 探活两个服务
      python canvas_cli.py doctor                          # 查配置：缺项才拉起服务并
                                                          # 打开 /settings.html
    python canvas_cli.py list <会话>                    # 所有页与框数
    python canvas_cli.py show <会话> <页>               # 看框：#编号 坐标 文字 来源
    python canvas_cli.py init <会话> <图片...>          # 新建会话（文件夹只放图片）
                                                        # 页码自动归一化成 5 位 NNNNN
                                                        # （按文件名排序顺序编号）
    python canvas_cli.py ocr <会话> [--pages 00003]     # 整页识别：只排队后立即返回
    python canvas_cli.py plan <会话>                    # 开工计划：页数/数据目录/实时地址/
                                                        # 步骤/节奏，一段话直接转给用户
    python canvas_cli.py next <会话>                    # 流水线取页：打印最早一页
                                                        # 已识别但未写 md 的页号
    python canvas_cli.py add <会话> <页> x1 y1 x2 y2 "文字"   # 新增框
    python canvas_cli.py rm <会话> <页> <编号...>       # 删除框，可一次给多个编号
    python canvas_cli.py rm <会话> <页> -1              # 删掉该页全部框（重来用）
    python canvas_cli.py scrub <会话> [页|all]          # 自动清空框/纯标点/单字噪声框
    python canvas_cli.py fix <会话> <页> --rm 3 --add 120,300,220,700 --text "文字"
                                                        # 原子改框：一次请求内删旧+加新，
                                                        # 避免删完索引错位导致反复试
    # 注意：md 和 audio_scripts 没有骨架命令，由 AI 直接写文件
    python canvas_cli.py voices <会话>                  # 查看角色声纹状态
    python canvas_cli.py check-characters <会话>        # 校验角色档案（字段/必填/音频文件）
    python canvas_cli.py check-audio <会话>             # 校验音频脚本（字段/说话人/台词/条数）
    python canvas_cli.py view <会话> all                # 全页并行 AI 校验（推荐）
    python canvas_cli.py view <会话> 00003,00004        # 指定多页
    python canvas_cli.py view <会话> 00003              # 单页
                                                        # 输出 PASS/FAIL + 可直接执行的 rm/fix 命令
    python canvas_cli.py vp <会话> [角色名 ...]         # 生成角色声纹（缺省=全部角色）
    python canvas_cli.py dlg <会话> [--page NNNNN] [--ref 对话N]
                                                        # 生成对话音频（不传 --page/--ref = 全部）

编号规则：show 输出的 #N 从 0 开始 = json regions 数组下标 = md 里的 @对话N。

**编号稳定性**：add 只把新框追加到末尾，已有框编号一律不变；
rm 会让被删编号之后的框各前移一位，这是数组下标的必然结果。
所以连续删多个框时，要么一条命令给齐 `rm 会话 页 3 5 7`（内部从大到小删），
要么删一次就重新 show。改文字一律用 fix，删+加在同一次请求内完成。

## 四、检查图接口 /render（agent 看图专用）

    GET http://127.0.0.1:7788/render?session=<会话>&page=<页码>&...

一次请求返回合成 JPEG：灰度底图 + 参考线 + 坐标标注 + 识别框。
参考线延伸到图片左侧/顶部边距，坐标标在图外（左侧数字旋转90°），
agent 从刻度直接读出原始像素坐标，禁止自己裁图。

| 参数 | 说明 | 默认 |
|---|---|---|
| session / page | 会话名 / 页码 | 必填 |
| grid=1 | 画参考线 | 关 |
| minor / major | 细线 / 粗线间隔（粗线亮、带坐标数字） | 50 / 100 |
| labels=1 | 边距上标坐标 | 关 |
| margin | 左/上边距宽 | 64 |
| rect | 裁剪 x1,y1,x2,y2（单个；x2<=x1 直接报错） | 整页 |
| focus | 着重橙框（分号分隔多个），强调区域不影响输出范围 | 无 |
| src_mode + idx | include/exclude 框，idx 为 #编号（JSON 下标） | 全部 |
| no_text=1 / mono_boxes=1 | 框不写文字 / 统一红色 | 关 |
| lw | 框线宽 | 2 |
| gray=1 | 灰度（黑白漫画建议开） | 关 |
| q | 底图压缩质量（只压底图，参考线/文字始终清晰） | 35 |
| scale | 底图缩放 0.25~1（0.5 体积降 4 倍，坐标标注自动换算回原值） | 1 |
| zoom | 输出放大 | 1 |

两层压缩：q 只压底图（agent 只需要大致坐标），参考线、坐标文字、框标签在压缩后的
底图上高质量合成，调 q 不会把参考线压糊。实测 00003 整页：q70 946KB →
q35+scale0.5 165KB → 加 rect 27KB。

调参可视化页：http://127.0.0.1:7788/render.html （左调参数右出图，底部 URL 栏
就是给 agent 的最终接口地址）。

**框校验的默认动作就是 view 一次**，不要先手工下载渲染图。它自动拉整页预览图 +
框数据 json，交给 settings.json 配置的视觉模型，返回 PASS / FAIL 和
可直接执行的 rm/fix 命令。三页并行约 13-15 秒。

手工 /render 的适用场景只有两个：需要确认某个具体坐标的细节，或 view 报的
坐标与实际画面对不上。不要用它来做常规校验。

## 五、工作流程

### 产物分工（重要）

| 产物 | 谁生成 | 说明 |
| --- | --- | --- |
| NNNNN.json（框） | 画布 OCR | 唯一必须走 HTTP 的写入 |
| NNNNN.md（分镜） | **AI 全文写** | 不套骨架，不引用 @对话N |
| NNNNN_audio_scripts.json | **AI 全文写** | 以 md 为唯一依据，不用脚本生成 |
| characters.json | **AI 全文写** | 发现新角色随时补 |
| 声纹 / 对话音频 | canvas_cli.py vp / dlg | 走豆包，收费 |

md 和 audio_scripts **都没有「骨架」这一步**。脚本能生成的东西只有框；
分镜和配音脚本必须由 AI 读完画面和 md 后自己写，因为要翻译错字、
判断说话人、设计语气和音效，脚本做不到。

### 第 1 步：确认配置和会话
    canvas_cli.py doctor          # 配置齐全就继续；缺项会打开 /settings.html
    canvas_cli.py check           # 真要跑 OCR 之前，确认 5009 也通
    并确认 sessions/<会话>/ 存在且含图片；没有会话用 init 创建。

### 第 2 步：整页 OCR
    canvas_cli.py ocr <会话>
    只负责把各页排进画布任务队列，命令立刻返回（后台识别）。
    结果写回每页 NNNNN.json。**ocr 没有等待参数，永远立即返回。**
    立刻把实时地址告诉用户：http://127.0.0.1:7788/?s=<会话>

### 第 2.5 步：流水线（每页一好就往下做）

    循环执行：
      canvas_cli.py next <会话>       # 打印最早一页已识别、还没写 md 的页号
      拿到页号 P 后立刻：
        canvas_cli.py scrub <会话> P
        canvas_cli.py view  <会话> P     # FAIL 就按命令修，再复验一次
        读原图 + show P，写 P.md 和 P_audio_scripts.json
    直到 next 返回「暂时没有可处理的页」且队列清空（就全部做完了）。

    页数少也一样：ocr 排队 → next 取页 → 处理 → 再 next，只是循环次数少。

### 第 3 步：框校验（一轮到底，最多两轮）

**标准做法：三条命令。**

    （页数多时按第 2.5 步逐页做，下面是页数少时的批量做法）
    1) canvas_cli.py scrub <会话> all        # 先一键清掉空框/纯标点/单字噪声框
    2) canvas_cli.py view  <会话> all        # 全页并行 AI 校验，直接给出修复命令
    3) 把 view 输出的 [CMD: ...] 逐条执行      # 删掉噪声框 / 补上漏框
       再跑一次 view <会话> all，ALL PASS 就结束这一大步。

就这么两轮。不要 show 逐页对照、不要逐框放大、不要为 check 结果反复截图。

判断口径（view 已内置，这里只是说明）：

- 漏框：有需要念出来的文字没被任何框罩住 → 按 view 给的坐标 fix/add。
- 噪声框：框罩住的是瓦纹、划痕、网点、拟声字、招牌、页码 → rm 删掉。
- 空框：text 为空或纯标点 → rm 删掉（scrub 已能处理大部分）。
- 文字有错别字 → **不管**（见铁律：只有意思完全读错才修）。
- 框边界略偏但字完整罩住 → **通过**。

一页框做完的唯一标准：有正文的地方都有框，框里不是噪声，且 text 没有读取错误。

**明确禁止的两件事**（这是 v2/v3 各花掉 8-12 分钟的地方）：

    × 下载整页渲染图然后自己看成十上百个局部放大图
    × 一边删框一边用旧编号继续删（编号会重排，必用 fix 或重新 show）

### 第 4 步：写分镜 md（每页一个 NNNNN.md，AI 全文写）

    **不用 canvas_cli.py md 生成的骨架。AI 看完这一页图后整份写出。**

    结构固定为四块：

    # NNNNN · 本页标题

    ## 页面信息
    - 页码 / 画面尺寸 / 阅读顺序（右→左）/ 出场角色 / 全页基调

    ## 场景描述
    ### 场景 A · 地点名（P1–P2）
    - 地点、时间与光线、环境、氛围
    （按场地拆分；一页只在一个地方时只写一个场景）

    ## 分镜
    ### P1 · 景别 · 一句话标题
    - 画面：具体画了什么，人物位置、动作、表情、构图、留白
    - 角色：谁在场，各自状态
    - 镜头：远景/中景/特写，机位与视角
    - 道具：关键物件（可省略）
    - 对话：
      > 角色名：完整台词
    - 音效：环境音与动作音

    ## 音效与配乐总表
    | 分镜 | 音效 | 说明 |

    铁律：

    - **对话直接写在分镜里，写完整台词**，不要写 @对话N 去引用 json。
    - 台词由 AI 改写：OCR 原文有错别字、或是英文/日文时，直接写正确的中文。
      不要照抄错字，也不要保留原文附录。
    - 分镜顺序 = 实际阅读顺序，不等于 json 里框的编号顺序。
    - 一句台词一格；同一格多人说话就写多行。
    - 拟声字（咚、咔嚓）写进「音效」或「画面」，不进「对话」。

    不要输出的东西：@对话N 引用、「对话引用」清单、框坐标、校对勾选框。
    这些都留在 json 和 view 的结果里，md 只写给人看和给配音用的内容。

    【输入：原图看一次 + 区域 json，就这两样】

        view_image  NNNNN.jpg          ← 整页原图，看一次
        canvas_cli.py show <会话> <页>  ← 框文字，命令读一次

    这两样合起来足够写完整页 md，不需要任何其他东西。

    具体做法：

    1. 先把整页原图看一遍，记住版面：哪几格、谁在场、什么场景。
    2. 再跑 show 拿到每个框的坐标和文字（这就是「区域 json」的内容）。
    3. 原图定「画了什么、谁在说」，show 的文字定「说了什么」。
       两者对上就写，写的时候错别字按文意改正。

    **不许下载、裁剪、放大任何局部。** 不建 .tmp 目录，
    不发 /render?rect=… 的请求，不为了「确认说话人」或「确认某个字」
    再看第二眼图。v4 在 md 阶段连下 12 张局部图，多花 7 分钟，
    产出质量和一次看完没有区别。

    拿不准的按规则落地，不要靠再看图解决：

    - 气泡尾巴指向谁 → 就是谁
    - 该格只有一个人 → 就是这个人
    - 一格多人都像、又没有尾巴 → 写「未知角色」，行尾注（画面上无法确认）
    - 字看不清 → 用 show 输出里的 text

    整页原图看不出说话人时，放大也看不出来——这是画法决定的，
    不是分辨率问题。宁可标「未知角色」，也不许反复放大。

### 第 5 步：配音脚本（每页一个 NNNNN_audio_scripts.json）

    **没有骨架命令。这个文件由 AI 读完 md 后整份写出来。**

    {
      "characters": {
        "喜织·狄狄": {
          "description": "外貌 + 性别 + 年龄感 + 声线特征",
          "voiceprint": "voices/喜织·狄狄.mp3",
          "ref_api":   "voices/喜织·狄狄_api_ref.mp3",
          "ref_final": "voices/喜织·狄狄_final_ref.mp3"
        }
      },
      "dialogues": [
        {"speaker": "喜织·狄狄", "page": "00003",
         "text": "那些家伙……到底怎样才能停下这种无意义的争斗！",
         "performance": "..."}
      ]
    }

    **这个文件也不需要额外看图。** 内容全部来自 md：speaker 抄分镜里的角色名，
    text 抄分镜里的台词，performance 按 md 的「音效」补上音乐与表演。
    md 写好了就不该再打开图片。

    - **text 从 md 里抄，用改好的中文**（不是 @对话N 引用，也不是 OCR 原文）。
    - dialogues 的顺序 = md 里分镜 P1、P2、P3 的顺序。
    - 不再使用 ref / tone 字段。
    - 这个文件里的 characters 只是本页出现的角色，声纹信息以会话级
      characters.json 为准；两处字段名不同是正常的，不要互相覆盖。
      本页 characters 的 description = 外貌 + 性别 + 年龄感 + 声线特征，
      给豆包生成这一页的音频时读。
    【performance 怎么写（豆包 audio-1.0 官方范式）】

    performance 是「这一段声音怎么演」的导演描述，写在台词前面。
    它只负责三件事：**情绪表演 + 背景音乐 + 音效**。

    音色不用写——音色由参考音频（@音频1）决定；没有参考音频时，
    canvas_cli.py dlg 会自动把 characters.json 里的 voiceprint_desc
    拼到 performance 前面（服务端本身不会带，是 CLI 补的）。
    所以在 performance 里重复音色是浪费，重点写下面三项：

    1) 情绪与表演：气息、语速、停顿、句尾怎么处理、副语言（轻笑/哽咽/吸气）。
       抽象词没用，要写可听见的行为。长句情绪有变化的按时间顺序写：
       「先…随后…最后…」。
    2) 背景音乐：乐器、节奏、情绪走向、什么时候进、什么时候收。
    3) 音效：环境音、动作音，写清什么声音、强度、什么时候出现。

    示例：
    「背景是低沉的大提琴持续音，音量很轻。男子压着怒气开口，气息粗重，
      语速偏快；说到『无意义』三个字时咬字加重、音量抬高；句末气息一沉，
      话尾收在一声很轻的呼气上。身边有折扇合拢的清脆轻响。」

    md 里每格已经写了音效，performance 直接沿用、补上音乐即可，
    不要另编一套和 md 冲突的声音。
    【characters.json —— 只有 6 个字段，不要加别的】

        {
          "神·宗一": {
            "name": "神·宗一",
            "appearance": "青年男性，二十五到三十岁。黑色长发在头顶束成高髻，
                           留短须。脸型偏长，鼻子挺直，眼睛细长。穿深色圆领官服，
                           腰系革带，跪坐时背脊笔直。",
            "voiceprint_desc": "青年男性，嗓音清亮微哑、语速平稳。献策时压低声音
                                贴近说话；急谏时音量抬高、节奏加快、尾音上挑。",
            "voiceprint_audio": "",
            "api_ref_audio": "",
            "final_ref_audio": ""
          }
        }

    - **appearance 是「在图上认人」用的**，必须写到能区分同类型角色。
      三个深色官服的中年男人，只写「朝臣」就会认错：
      一个戴黑乌帽留八字胡，一个束小髻圆脸短须，一个高髻长脸短须。
    - 不要加 personality / role / expression_set / voice_settings /
      appears_in_pages 之类的字段，用不到。
    - 扁平结构（名字 → 档案），不要写成 {"characters": [...]}，
      否则 vp 命令报 "'list' object has no attribute 'get'"。
    - 名字未知时用「未知角色A/B」，但 appearance 仍要写具体。

### 第 6 步：声纹与对话音频（豆包 audio-1.0）
    前置：/settings.html 里配好豆包 API key（只需配一次）。

    **全部用 CLI，不要开浏览器**（页面只是人工试听时用的）：

        canvas_cli.py vp  <会话>              # 生成全部角色声纹
        canvas_cli.py vp  <会话> 旁白 神·宗一  # 只生成指定角色
        canvas_cli.py dlg <会话> --page 00003 --ref 对话4   # 抽查一条
        canvas_cli.py dlg <会话>              # 生成全部（已生成的自动跳过）
        canvas_cli.py dlg <会话> --force       # 强制全部重生成（会花钱）

    dlg 默认跳过 voices/ 里已有的同名音频，避免重复计费；要重做才加 --force。

    【角色还没有声纹 / 参考音频时怎么办】

    音频引用分三种情况，服务端自动处理，不需要在脚本里判断：

    1) 角色有 final_ref_audio（通常是生成过声纹）：
       performance + 「@音频1 说道："台词"」，音色由参考音频锁定。
    2) 角色没有任何音频：
       performance + 台词直接成句，服务端会把 characters.json 里的
       voiceprint_desc 作为音色说明一起送去生成。
    3) 需要临时换音色：先把参考 mp3 上传到 voices/，在 characters.json
       里填上 final_ref_audio，之后的对话都会用它。

    所以「没生成声纹就先引用声纹描述」是支持的，直接跑 dlg 即可，
    不用先跑 vp。先 vp 只是为了让同一角色在所有台词里音色更稳定。
    canvas_cli.py voices <会话> 随时查看声纹状态。

### 第 7 步：验收
    - 每页：所有要念的文字都有框、文字正确（允许标点差异）
- 每页：NNNNN.md（场景 + 分镜 + 完整台词 + 音效）与 NNNNN_audio_scripts.json 齐全
    - 会话：characters.json 齐全、每角色有声纹描述与声纹音频
    - 全程操作在画布前端可见（写入走 CLI → SSE 实时刷新）

### 模板 2 · NNNNN_audio_scripts.json

```json
{

    "喜织·狄狄": {
      "description": "年轻男性，二十岁出头，黑色长直发垂到肩胛，素白宽袍。嗓音低沉偏清、带气声。",
      "voiceprint": "voices/喜织·狄狄.mp3",
      "ref_api": "voices/喜织·狄狄_api_ref.mp3",
      "ref_final": "voices/喜织·狄狄_final_ref.mp3"
    }
  },
  "dialogues": [
    {
      "speaker": "喜织·狄狄",
      "page": "00003",
      "text": "那些家伙……到底怎样才能停下这种无意义的争斗！",
      "performance": "背景是低沉的大提琴持续音，节奏像心跳。开口时压着怒气，声音发紧、气息粗重；『那些家伙』拖长；『无意义的争斗』咬字加重、音量抬高；句末气息一沉，收在短促的呼气上。伴随一声折扇合拢的脆响。"
    }
  ]
}
```

要点：

- dialogues 每条**只能**有 `speaker` / `page` / `text` / `performance` 四个字段。
- 不要 `ref`、不要 `tone`、不要 `id`、不要任何别的键。
- `text` 从 md 抄，是改好的完整中文。
- `performance` 写情绪表演 + 背景音乐 + 音效，不写音色。
- 顺序 = md 里 P1、P2、P3 的顺序。
- 这里 characters 只列本页出现的角色，声纹信息以会话级 characters.json 为准。

### 模板 3 · characters.json

```json
{
  "喜织·狄狄": {
    "name": "喜织·狄狄",
    "appearance": "年轻男性，二十岁出头。黑色长直发垂到肩胛，中分。面容清秀偏阴柔，眉毛细长上挑，眼睛狭长、眼尾上扬。穿素白宽袍，敞领，腰束深色带，手持折扇。",
    "voiceprint_desc": "中青年男性，嗓音低沉偏清、带气声。疲倦时语速慢、句尾下沉；发怒时声音发紧、咬字加重；兴奋时音量抬高、语速加快。",
    "voiceprint_audio": "",
    "api_ref_audio": "",
    "final_ref_audio": ""
  }
}
```

要点：

- 扁平结构：顶层是 `名字 -> 档案`，**不是** `{"characters": [...]}`。
- 每份档案**只有** 6 个字段，多一个都会让校验命令报警。
- `appearance` 是「在图上认人」用的，必须写到能区分同类型角色。
- `voiceprint_desc` 不能为空：没有声纹音频时，dlg 会用它当音色说明。
- 三个音频字段留空字符串表示还没生成，不要填不存在的文件名。

## 交付前自检（必跑）

    canvas_cli.py check-characters <会话>   # 角色档案：字段、必填、音频文件是否存在
    canvas_cli.py check-audio <会话>        # 音频脚本：字段、说话人、台词、条数、覆盖率

两条都输出「通过」才算完成。有 [错误] 就必须修，
[提示] 是警告（例如 appearance 太短），建议看一眼再决定。


### 覆盖率自检（check-audio --coverage）

台词允许改写，但不该悄悄缩水。这条检查把每条对话的 text 和
该页 json 里最相近的框原文做比对，算「原文有多少比例被保留下来」。

    canvas_cli.py check-audio <会话>                  # 默认 90%
    canvas_cli.py check-audio <会话> --coverage 1.0   # 要求逐字一致
    canvas_cli.py check-audio <会话> --coverage 0.75  # 允许大幅精简

判定规则：

| 覆盖率 | 结果 | 说明 |
| --- | --- | --- |
| >= 95% | 通过 | 基本原样保留 |
| 90%-95% | 提示 | 有少量改写，看一眼即可 |
| < 90% | 错误 | 可能漏字或过度精简，需要修 |
| < 50% | 提示 | 多半对错了框，不是漏字 |
| 框没用上 | 缺漏 | 有正文框的内容没进任何对话 |

**哪些框不参与比对**：名牌（带空格的身份标注，如「独立州 当代国主 喜织·狄狄」）
和短的地点标注（「独立州幕府中」「独立州首都 东区某商业街」）会自动跳过，
它们本来就不该进对话。

**改写的边界**：漫画台词常常水分很大，允许在保持原意的前提下精简，
但不要因为「句子啰嗦」就砍掉一半。要大幅精简就调低 --coverage，
让阈值和你的意图一致，而不是让检查形同虚设。

注意「原文 139 字，现在 153 字」这种情况：说明多条旁白被合并成了一条，
覆盖率会偏低，但内容其实没少。对照一眼 md 确认即可。


#### 检查能发现什么

1. **某条对话被砍短**：报「覆盖率 81%，原文 76 字，现在 27 字」。
2. **整条对话被漏掉**：报「框 #9 只有 60% 的内容进了对话，可能漏了」——
   这是反向检查，每个正文框都必须有内容进到对话里。
3. **多条框合并成一条对话**：报「合并了 2 个框（#0~#1）」，合并本身允许，
   但会提示你确认没漏内容。
4. **一条框被拆进多条对话**：报「框 #N 的内容被拆进多条对话」。
   相邻框在匹配时的正常重叠不会误报。

没有任何提示 = 每条对话都对得上原框，且没有框被漏掉。



## 七、常见坑

- **本流程的实测基准**（3 页、32 框，v4 校准后的成绩）：
  探活 1.5s + OCR 12s + scrub 1.5s + view 两轮 50s + md/scripts 11s
  + 声纹 97s + 抽查 2 条音频 38s ≈ **4 分钟**。
  框校验合计 52 秒。若你的框校验超过 2 分钟，说明又在逐框放大或重复 view。
  写 md 阶段若超过 1 分钟／页，基本可以断定又在下载局部图。

- **别手工看渲染图**。view 一次就能列出全部问题并给出可执行命令；
  自己下载图片逐个看是 v2/v3 耗时的一半来源。
- **删框后编号会重排**。要改框用 fix（一次请求内删+加），不要 rm 之后
  还按旧编号继续删。
- **scrub 只删确定是噪声的框**：空文本、纯标点、单字且低置信度。
  长文本即使 prob 很低也保留——OCR 置信度对长段落不可靠，误删正文会返工。
- **view 超时就原样重试一次**，不要因为一次超时改成手工看图。
- **三页以上用 view <会话> all**，内部并行，一页十几秒会压到总时长十几秒。

- 画布「整页 OCR」单遍检测会漏，只当草稿；漏框靠检查图逐页找，不要指望一次跑对。
- 检查图 q 只压底图，参考线/坐标文字始终清晰；scale=0.5 整页扫体积降 4 倍。
- rect 填 10,10,10,10 这种 x2<=x1 的值会直接报错（不会静默返回整页）。
- 检查图读坐标：刻度标注的就是原始像素值，不用自己换算；裁剪后左上角标 x/y 偏移。
- OCR 服务刚启动 /health 可能 20-40 秒后才通，别重复启动
  （`manga-panel-studio check` 探活，DOWN 就再等等）。
- Windows 控制台先设 $env:PYTHONIOENCODING='utf-8' 再跑 CLI。
- 不要直接修改 sessions/ 里的数据文件（一切写入走画布 HTTP 接口，才能留历史、
  触发前端刷新）；设置与音频页面已合并进主服务。
- 说话人判断靠画面证据（气泡尾巴、视线、张嘴），拿不准就写「未知角色A」。
- settings.json 缺项时不要硬着头皮跑 OCR / 配音：先让用户在 /settings.html 填好。
  doctor 会告诉你具体缺哪几项，缺 key 的报错一般是 401 或「还没保存豆包 API key」。
